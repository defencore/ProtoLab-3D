# Connectors and interfaces organization audit

Historical section review, 2026-11-03, before curator integration. Some recommendations below were implemented in the same organization pass; use the [integrated review](../library-organization-audit.md) for completed changes and remaining work. Runtime counts describe that review snapshot. Raw snapshots and logs are optional local evidence under ignored `test-results/`; this document preserves the section findings in the repository.

Scope: all 9 current packages, 108 presets and 8 navigation entries. Root is the library curator. Source/schema and metadata inspection only; source files were not changed and no package, geometry or CAD tests were run.

## Immediate safe metadata corrections

1. `cable-gland/presets.json`: use **Cable gland · Ø6 mm cable** and **Cable gland · Ø10 mm cable**, and align the Variants list in GUIDE. Existing names omit the dimensional unit. Preserve IDs and all numeric values.
2. SRS GUIDE paths are stale: `srs-connector` says Electronics & vision / Connectors & wiring, while `srs-retainer` and `srs-igniter` also retain Electronics & vision. Use **Connectors & interfaces → SRS airbag** and the current singular family names.
3. `waterproof-connector/GUIDE.md` should direct users to **Connectors & interfaces → Power & industrial → Power & industrial connectors**, then the SP article in the shared chooser. It currently teaches a standalone SP library row that grouping hides. Apply the same shared-catalog path clarification to the AMASS guide.
4. `signal-connector/GUIDE.md` still says 35 references while current presets/catalog contain 40. Reconcile the Included models summary against the current retained assets; do not infer the extra models from counts alone.
5. Physical package names `AMASS power connectors` and `SP waterproof connectors` are plural, contrary to the singular type convention. Optional singular physical titles would improve consistency, but shared navigation already supplies a concise common name. Preserve supplier article titles and IDs.

## Parameter/state follow-up

- `waterproof-connector.panelThickness` already has correct `visibleWhen` for panel sockets. It must remain an installation study, not a published panel-thickness rating. SP16 and SP20 dimensions remain independent; do not scale one to form another supplier execution.
- `laboratory-terminal/configurator.ts`: the colour control is always hidden (`visibleWhen: () => false`), although validation permits red/black for spring-lever clips. If this is intended as a user choice, make availability model-aware and reconcile it when switching to a non-clip. If it is assembly-only appearance, state that explicitly rather than exposing a dormant normal control. This is not a new procurement option.
- `cable-gland/GUIDE.md` claims body, compression nut and seal envelope; `lib/model.ts` currently emits only body and nut. Align the documentation with implemented physical scope, or register and validate a real seal design separately. Do not add an invented seal merely to satisfy prose.
- `signal-connector` deliberately offers only one assembled state: several retained community models fuse material regions, so an artificial exploded view would misrepresent the source. The SRS retainer likewise has one canonical physical state. Other inspected families have actual multiple components for their inspection state; no universal state cleanup is indicated for this section.
- Parameter group titles vary between Model, Product, Connector selection and Terminal selection. A future cosmetic normalization can use a predictable Product/Installation order without renaming stable keys. Keep source characteristics, appearance and editable harness/installation controls distinct.

## Evidence and limits

Reviewed the runtime snapshot, all nine `part.ts` and preset files, related configurators and guides, cable-gland geometry factory, and library catalog declarations. No duplicate physical definition was established by this section audit. No current, voltage, IP, sealing, mating or native-CAD qualification is implied. In particular, SP supplier kits, SRS incomplete order suffixes, PCB community source models and RF omitted cable scope retain their documented limitations.
