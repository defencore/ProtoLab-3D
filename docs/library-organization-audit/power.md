# Power and motor control organization audit

Historical section review, 2026-11-03, before curator integration. Some recommendations below were implemented in the same organization pass; use the [integrated review](../library-organization-audit.md) for completed changes and remaining work. Runtime counts describe that review snapshot. Raw snapshots and logs are optional local evidence under ignored `test-results/`; this document preserves the section findings in the repository.

Scope: all 16 current `POWER & MOTOR CONTROL` packages, 72 presets and 12 navigation entries. Source and metadata inspection only; no source files were changed, and no package, geometry or export tests were run by this analyst.

## Immediate safe metadata changes

1. `cnc-servo-drive/part.ts`: selector label `Delta ASD-A3-0721-M ·750W200–230VAC` compresses several physical quantities. Use the canonical preset title, or a consistently spaced `Delta ASD-A3-0721-M · 750 W · 200–230 V AC` title in both selector and preset. Keep the actual model value, source designation and procurement metadata unchanged.
2. Standardize fixed-model control labels such as **Model** or the actual product type. Current BEC/ESC/converter `Board / module model`, pack `Model`, UPS `Module`, and HAT `Servo driver` are individually understandable but inconsistent. Keep all stable keys.
3. BEILAMOO holder presets start with only `2S1P`, whereas MPD presets start with the manufacturer. Prefix source-established BEILAMOO names with the manufacturer to identify articles in the shared holder catalog. Synchronize `lib/models.json` names and selector titles; keep source designation and CAD identity unchanged.
4. `machine-control` emergency-stop title uses `D40`; prefer `Ø40 mm` while keeping `XB5AS8444` intact. Use `·` separators for independent voltage/current characteristics in curated visible titles. Supplier designations remain unchanged.
5. Evidence limitations such as `installation reference` and `reference` in the BEC/filter/user-switch preset titles should live in descriptions and evidence badges, following the naming policy. Retain a physical distinguishing phrase where required, e.g. the filter's selected 16 × 6 mm seller execution. Do not erase the explicit engineering-reference classification or missing source evidence.
6. Canonical state labels vary between **Assembled**, **Assembly** and **External assembly**. A later metadata consistency pass can use **Assembled** while preserving state IDs and explaining the supplied-unit boundary in descriptions.

## Parameter and state issues requiring targeted validation

- `battery-holder/lib/model.ts:pieces()` adds exactly one `Cell tray`, then calls the shared `finish()`. The generic **Exploded** choice is therefore identical to Assembled. Remove or disable that ineffective inspection choice only with saved-state reconciliation and affected preview/native checks. Do not invent contacts or procurement components to justify it.
- `li-ion-battery-holder/lib/model.ts:holderComponents()` actually separates native metal spring contacts from plastic for Exploded. Retain that implemented state without decomposing the purchased holder into extra BOM purchases.
- `pwm-switch` already constrains Exploded with `availableWhen` and validation for the unidentified user reference; retain this pattern.
- `panel-battery-module` uses meaningful lid/lock/printing/template states and explicit library composition. Host panel thickness and reference-cell display remain installation/inspection controls, not new package identities. Dimensional/model consolidation must preserve the reference-only display and physical export distinction.
- The industrial-control catch-all cannot be repaired by moving its whole package to Switches or Power supplies: each preset has a different function. A later model-aware navigation design or explicit physical-family split should map VFDs, PLCs, supplies, motion controllers, safety equipment and the emergency stop to their proper functions. Such work needs a reviewed migration of existing `machine-control:<preset>` references; copying a sourced device into another family would create duplicate identities. No immediate split is recommended without that migration.

Reviewed the runtime snapshot, every local preset list, family classifications, relevant `part.ts`/`configurator.ts` files, native holder assembly construction and generic battery-tray construction. Read model/source metadata and guide distinctions for UPS, cells, packs, holders and the panel assembly. Evidence paths include `src/core/library.ts`, `src/parts/battery-holder/lib/model.ts`, `src/parts/li-ion-battery-holder/lib/model.ts`, `src/parts/pwm-switch/part.ts`, `src/parts/panel-battery-module/part.ts`, `src/parts/machine-control/configurator.ts`, and their local presets/GUIDEs.

This audit establishes organization findings, not electrical compatibility, battery safety, thermal performance, electrical ratings, mechanical fit or production readiness. Appropriate integration checks are package registration, shared catalogs, naming, exact-ID search, project/ESKD identity retention and affected state/composition tests. Native geometry checks become necessary if geometry or state behavior changes.
