# Electronics and vision organization audit

Historical section review, 2026-11-03, before curator integration. Some recommendations below were implemented in the same organization pass; use the [integrated review](../library-organization-audit.md) for completed changes and remaining work. Runtime counts describe that review snapshot. Raw snapshots and logs are optional local evidence under ignored `test-results/`; this document preserves the section findings in the repository.

Scope: all 31 current `ELECTRONICS & VISION` packages, 149 runtime presets and 24 initial navigation entries. Source and metadata inspection only. No source was edited and no geometry, package or export tests were run by this analyst.

## Immediate safe metadata improvements

1. `machine-measurement/configurator.ts` and `presets.json`: change `Kuebler MWE21 · C200 · encoder1000 ppr` to `Kuebler MWE21 · C200 · encoder · 1000 ppr`. Keep source execution and geometry unchanged.
2. Add generic browse labels instead of changing physical supplier identities: `cnc-linear-encoder` → **Linear encoders & mounting spars**; `m2-ssd` → **M.2 NVMe SSD**; optionally `gps-tracker` → **GPS tracker** and `recovery-buzzer` → **Recovery buzzer**. If the finder catalog is adopted, its shared title supersedes the latter standalone label.
3. `board-camera-19:imx577-19x19-rear-mipi-m25`: normalize the curated preset title to **IMX577 19 × 19 mm CSI camera · rear MIPI · M2.5 mounts**. Keep actual camera dimensions and both reference identities unchanged.
4. LED model titles currently use shout-style `LEDS` and compact `1×8`. Prefer **WS2812B stick · 8 LEDs**, **WS2812B matrix · 2 × 2 LEDs**, **WS2812B ring · 12 LEDs**, etc. Keep canonical titles synchronized between local model catalog and presets; preserve original supplier `catalog.name`/designation and any generator that owns these records.
5. The optional recovery catalog should retain exact IDs and independent source attributes, particularly the source-project `jhe42b-project-reference-26x17x15`; its dimensions cannot inherit the standard JHE42B ratings or resolve the manufacturer's existing dimensional conflict.

## Definite duplicate product coverage needing a migration decision

`machine-measurement:e2b-m12` and `cnc-limit-sensor:e2b-m12` both identify **OMRON E2B-M12KS04-WP-B1 2M**, cite the same manufacturer catalog and represent the same nominal short-body installation reference. `cnc-limit-sensor/part.ts` directly imports `machine-measurement/part.ts` and delegates `buildGeometry`, `dimensions` and `python` to its fixed `e2b-m12` model; the dedicated wrapper additionally appends purchased-unit metadata. This is stronger evidence than a similar-looking shape: it is overlapping library identity for the same stated product.

Do not delete either ID during an organization-only pass. Choose a canonical definition deliberately, map all assembly dependencies and occurrences to it, retain supplemental source metadata, and migrate saved configuration/project references with exact-ID and ESKD round-trip tests. A shared catalog alone would hide neither the duplicate qualified IDs nor the resulting risk of duplicate project product definitions. No such identity migration or product-equivalence test was performed here.

Raspberry Pi 5's `raspberry-pi-5` and `raspberry-pi-5-full` presets share the same bare-board product and differ in detail level; they are inspection/detail examples, not independent supplier SKUs. The existing `detail` parameter is the correct model axis. Preserve current IDs until any preset cleanup has explicit configuration identity tests.

## State and parameter follow-up

- `heat-sink/lib/model.ts` always adds one fused `Heat sink` piece, in both envelope and detailed modes. Its generic `exploded` state passes through `finish()` unchanged; remove it from available selection only with saved-state reconciliation and affected export checks. Fins are integral geometry, not independently purchased or assembled pieces.
- Cooling fan, recovery buzzer and GPS tracker have several explicitly separated visualization pieces; their inspection states do change geometry. Their source units remain opaque procurement products. Do not turn visual electronics, batteries or contacts into separate procurement rows.
- Generic `industrial-sensor` already parameterizes proximity, rotary encoder and roller limit forms. These are engineering references, while fixed OMRON/HEIDENHAIN parts retain source-owned dimensions; a common navigation group must never make the latter dimensions freely editable.
- `cnc-linear-encoder` selects LS 477 encoder kits and separately purchased MSL 41 spars through `model`; `component` is an inspection selection and `headPosition` an inspection pose. Check that scale/readhead choices and displacement controls are unavailable or reconciled for spar models before calling all combinations meaningful.
- `flight-controller` WING MINI mounting pitches are explicitly labeled installation assumptions. They must remain conditional, non-filterable reference fields and must not become fixed manufacturer dimensions.
- Parameter group labels vary between Model, Catalog, Supplier component and Configuration. Prefer consistent visible group terminology for new work, while preserving existing keys and distinguishing product selection from source attributes and inspection pose.

## Evidence and validation boundary

Reviewed runtime metadata, every package's local preset IDs, shared catalog membership and model schemas, plus targeted `part.ts`, `configurator.ts`, `lib/model.ts` and GUIDE files. In particular: E2B wrapper delegation and source records; fixed camera/CM5/LED selections; board-camera reference provenance; JHE42B standard vs project reference; fan and heat-sink piece construction; WING MINI conditional mounting references; HEIDENHAIN execution and inspection selectors. This audit does not verify source dimensions, optical behavior, electrical compatibility, mechanical fit, thermal performance or native topology. Integration should run naming/catalog/identity tests and affected package checks; geometry or identity consolidation additionally requires the project engineering verification workflow.
