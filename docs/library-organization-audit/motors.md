## Immediate safe changes

1. Extend `brushless-motors` in `src/core/library.ts` with `surpass-2838` and `surpass-2845`. Both already have the same functional category/subgroup and fixed preset-based model selectors. Their published dimensions and KV stay per model. This removes two standalone brand/size rows without merging source geometry.
2. Add shared `servo-horns` with `servo-arm` as primary and `metal-servo-horn` as another member. The authored horn family already supports single, double, cross, six-arm and disc forms as parameters. The retained native metal source remains its own purchased product. Do not absorb `servo-gear` merely because both have servo splines.
3. Add `cnc-spindle.browseLabel: 'Spindle motor'`; its current title includes the implementation phrase `manufacturer drawing execution`. Keep evidence in descriptions/GUIDE and exact executions in preset names. Keep its existing ID.
4. When selector labels are curated, fix missing spaces such as `·24 V` in `cnc-feed-servo` and spacing in related source explanatory notes. Do not change supplier codes or numeric ratings.
5. Consider moving `chf-gf5560-180` from DC & industrial motors into Motor assemblies and changing its shared membership from `dc-motors` to `gearmotors` together. A partial move would violate common category/subgroup constraints. Its own source name already states worm gear motor. This is a navigation correction, not a claim of interchangeable mounting with GMP or other gearmotors.

## Parameterization and deeper refactors

The 17 TR8/SFK packages are not proven duplicates merely because many share four angle controls and a motor selector. Output count, disc diameter, central/twin-pin guide arrangements, laser versus CNC frames, motor mounting, coupling geometry and purchased bearing sets differ. The existing shared catalog is the safe interface consolidation. Already implemented choices such as `motorModel`, `bearingKit`, `discPattern`, `crankConstruction` and `screwModel` stay inside their execution. A single generalized geometry engine would require a deliberate top-down interface model plus all affected composition, source and native export regression checks.

Surpass 2838's seven windings and 2845's one execution are fixed products. Their selectors already preserve complete preset names. Do not resize the 2838 body to synthesize 2845 or rename the published 3500 KV winding to a later 3600 KV listing. Both explicitly declare `physicalStates: ['assembled', 'cross-drilled']`; the custom transverse shaft hole is secondary manufacturing with a separate physical identity, not an exploded inspection option. Preserve this distinction through the common chooser.

State labels currently mix Assembly, Assembled, Manufacturer model and Installation model; labels can be made more consistent without changing IDs, but the last two communicate reconstruction scope and need concise descriptions if relabeled. Servo horn Top side/Socket side are inspection orientations, not different procurement units. `holding-electromagnet` magnet-only/armature and `open-frame-solenoid` frame-only are component display selections with no explicit physicalStates declaration; clarify intended procurement/physical composition semantics before changing identity. `worm-fin-actuator` also exposes several manufactured component-only inspection selections; its canonical composition must remain the complete mechanism. No no-op Exploded state was established in the inspected multi-piece motor factories.

## Evidence and verification boundary

Reviewed runtime schema/state metadata for every package; source `part.ts` and configurators for Surpass, generic/fixed motor groups, servo horns, spindle, TR8 Faulhaber/Surpass/geared variants and component-only state definitions; source guides for the Surpass installation reconstructions. `src/core/library.ts` and shared catalog tests establish current grouping contracts. No external source research was needed for these organizational findings, and no new engineering calculations or mechanism redesign was undertaken. Integration must check catalog membership, selector/search behavior, exact-ID resolution, source/model retention, project identities and affected package contracts. Native geometry verification is required if a later refactor changes factories, not implied by this metadata audit.
