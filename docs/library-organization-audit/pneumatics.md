# Pneumatics and gas organization audit

Historical section review, 2026-11-03, before curator integration. Some recommendations below were implemented in the same organization pass; use the [integrated review](../library-organization-audit.md) for completed changes and remaining work. Runtime counts describe that review snapshot. Raw snapshots and logs are optional local evidence under ignored `test-results/`; this document preserves the section findings in the repository.

Scope: all 12 current `PNEUMATICS & GAS` packages, 53 presets and 12 navigation rows in `before.json`. Source-only organization/schema review; no source files changed, no package, native geometry or export tests run.

## Immediate safe changes

1. Add `cylinders` shared browse catalog, label **Cylinders**, using `fluid-cylinder` as primary followed by the three source-model packages above. All already share category/subgroup. This reduces section rows from 12 to 9 while preserving every real configuration.
2. Keep fixed source dimensions selected by model/bore/stroke; keep rod extension as an operating pose. Use consistent visible group **Operation** or **Pose** for extension, rather than `Dimensions` in generic cylinders and `Assembly position` in round cylinders. Preserve keys and values. The generic label `Rated geometric stroke` should become **Geometric stroke**: the guide explicitly disclaims performance ratings.
3. Normalize `fluid-hose` preset labels to **Straight tube · Ø10 mm OD · Ø6 mm ID** and **Tube elbow · Ø10 mm OD · Ø6 mm ID**, rather than an unexplained slash. `pneumatic-valve` first model can use **4V210-08 · 5/2 · 24 V DC**, updating its model selector and preset together; source designations remain unchanged.
4. `profile-pneumatic-cylinder` bore/stroke source filters and `round-pneumatic-cylinder` equivalents can share visible labels and parameter groups while retaining per-model source facts. The compact family currently has source catalog presets but no `catalogFilterFields`; populate published bore/stroke attributes from its evidence before expecting those characteristic filters to cover every cylinder. Do not infer published characteristics from generic editable preview dimensions.
5. Keep the generic fluid references clearly labeled through evidence/product type. Do not turn a nominal BSP/metric diameter into a thread specification or interpret a cartridge's fill mass as gross product mass.

## State/schema findings requiring separate validation

- `fluid-hose/lib/model.ts` and `vacuum-cup/lib/model.ts` emit exactly one piece for every configuration, but their definitions offer `assembled` and `exploded`; the shared `finish()` cannot separate a singleton. Remove unavailable/no-op inspection choices only with saved-state reconciliation and applicable native checks.
- `fluid-fitting` emits a separate release collar only when `connection === 'push'`. Exploded availability should be conditional on that configuration. All non-push connection forms emit only one body. JIC and ORFS construction remain generic interface references.
- The fixed round and profile cylinder packages correctly avoid invented exploded interiors. Compact AirTAC exposes no model state. CO2 has one meaningful sealed state. Their catalog models remain purchased procurement units even when display solids are multiple.
- Generic cylinder extension currently sits under editable dimensions; selection should distinguish design stroke from operating extension. The fixed round/profile implementations already reconcile extension on model changes; preserve those limits through catalog selection.
- The `fluid-valve` family mixes functions under one broad schema. Splitting valve/FRL/ejector functionality would be a semantic schema and physical-state task, not an ID cleanup. Existing generic controls do not prove pneumatic circuit function.

## Evidence and limits

Inspected every package's `configurator.ts`, `presets.json` and `GUIDE.md`; inspected compact cylinder `part.ts`, and singleton/conditional piece generation in `fluid-hose`, `vacuum-cup` and `fluid-fitting`. Fixed supplier guides explicitly record missing mounting dimensions and source limitations; existing historical verification records were read, not rerun. The catalog grouping proposal preserves their limitations and original installed source references.

Integration checks should cover curated membership, exact-ID search, reference versus purchased classification, model switching/extension bounds and project identity round trips, plus affected package checks. Any state or geometry change additionally requires the corresponding generated CAD checks. This audit establishes organization findings only, not pressure, flow, load, mounting accuracy or manufacturing readiness.
