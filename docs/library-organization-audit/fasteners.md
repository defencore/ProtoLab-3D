# Fasteners and threads section audit

Historical section review, 2026-11-03, before curator integration. Some recommendations below were implemented in the same organization pass; use the [integrated review](../library-organization-audit.md) for completed changes and remaining work. Runtime counts describe that review snapshot. Raw snapshots and logs are optional local evidence under ignored `test-results/`; this document preserves the section findings in the repository.

Scope: current worktree metadata/schema and source inspection. 39 physical packages, 8,756 presets, 16 current navigation families. No package, geometry, CAD or persistence tests were run by this analyst. No source was modified.

## Immediate safe naming and organization changes

1. Add the lifting-eyes shared catalog in `src/core/library.ts`, choosing `lifting-eye-bolt` as its primary and retaining category `FASTENERS & THREADS` / subgroup `LIFTING EYES`. This removes one redundant navigation choice without changing supplier geometry or product type.
2. `wing-nut/presets.json` currently titles articles simply `M3`, `M4`, etc., although each catalog record explicitly names DIN 315. Prefer `M3 · DIN 315` etc. This is particularly valuable inside the shared Nuts model list. Preserve catalog source titles, source designation, source URLs, verified dimensions and SKUs.
3. `e-ring/presets.json`: prefer `Ø1.2 mm · DIN 6799`, retaining the actual source designation independently. The current title omits an established standard. `lifting-eye-nut` similarly benefits from `M8 · DIN 582`; preserve its explicit `M6 · non-standard size` exception rather than claiming that execution complies with the standard.
4. `cotter-pin/presets.json`: current `1 × 8 · DIN 94` lacks diameter indication and units; use `Ø1 × 8 mm · DIN 94`. This does not change the nominal size semantics or the approximate eye/bend geometry noted in evidence.
5. `printed-pin-joint/presets.json` and `printed-snap-joint/presets.json`: use `·` between independent characteristics rather than `/`, e.g. `Ø6 mm pin · 0.30 mm diametral clearance` and `24 mm beam · 0.3 mm side clearance`. The two clearance definitions are different; do not relabel both as radial or diametral.
6. `spacer/presets.json`: `PCB · 10 mm` and `General · 15 mm` are vague selections in a four-member shared catalog. Prefer complete authored sizes such as `Ø6 × 3.4 bore × 10 mm` or readable equivalent with explicit outside/bore/length labels. Do not introduce an M3 thread designation for an unthreaded clearance bore.
7. Preserve literal DREMEC order codes such as `111x5` and `324/2.1x10`; these are supplier identifiers, not arbitrary dimensional typography to rewrite. Add explanatory size metadata alongside them only if needed.

Naming corrections for generated catalogs must update their offline adapters as well as the package snapshot: `scripts/sync-package-catalogs.ts` calls `src/catalog/hand-nuts.ts` for wing/lifting nuts and the cotter adapter for cotters. `handNutPresets()` still emits a `maximum envelope` title suffix for wing nuts; this conflicts with the naming policy that evidence limitations belong in descriptions. A future explicit catalog sync could undo a snapshot-only naming fix or restore that unwanted suffix.

## Parameter and state findings

- `dowel-pin`, `t-slot-nut` and `threaded-insert` each emit exactly one component in `lib/model.ts`, but declare generic `assembled` and `exploded` states in `part.ts`. `src/core/assembly/mechanical/helpers.ts:finish()` returns the same pieces for fewer than two components. Thus Exploded is a no-op by source inspection. Remove it from available choices only with deliberate saved-state reconciliation and applicable geometry/identity tests; do not invent extra product parts merely to make an exploded view.
- `blind-rivet` legitimately has two displayed pieces (sleeve and pull mandrel); retain inspection separation while preserving the purchased procurement boundary.
- `dowel-pin/configurator.ts` correctly hides taper for straight pins, but its taper step is `0.1` while default/preset taper is `0.02`; a practical finer step should be reviewed. This is UI control resolution, not a changed pin standard.
- `threaded-insert` already has heat-set, press-fit, rivet-nut and self-clinching forms. Its detail control is preview construction detail rather than a model state, but the nominal bore does not define a real thread profile. Do not advertise these generic prototypes as exact purchased products.
- `split-lock-washer` Free/Flattened, `spring-pin` Free/Installed, `cotter-pin` Straight/Bent and printed joint Assembled/Exploded/Print have physical or inspection meaning. Keep thread Simple/Full detail outside state selections.
- `thread-tool` External/Internal changes male/female geometry, rather than inspection pose. Its product profile is a reference; any future production-use adaptation needs explicit physical-state/identity review. Do not merge it into purchased screw/nut catalogs merely because the thread dimensions overlap.
- Thread diameter keys differ (`diameter` vs `bore`) across existing wrappers. Preserve stable keys; label the physical meaning consistently instead of renaming keys solely for style.
- Fixed `pcb-standoff` and `pcb-standoff-insert` source-owned geometry fields are hidden and validated through the selected `catalogItem`; material/coating, end forms, metric/UNC interfaces and unknown depths remain source data. `spacer` is an editable manufacturing design; `dremec-spacer-sleeve` is explicitly customer-specified ordering, not stock SKU synthesis. No consolidation of these APIs is necessary for logical browsing.

## Evidence and verification boundary

Reviewed the runtime inventory and every package's preset IDs/names/counts; reviewed family catalogs, wrapper schemas, targeted geometry factories and guides for overlapping nut/standoff/printed-joint/insert/pin definitions. Relevant files are `src/core/library.ts`, `src/core/library-identity.ts`, `src/core/assembly/mechanical/helpers.ts`, `src/core/hardware/nuts.ts`, `src/parts/*/part.ts`, `src/parts/*/presets.json`, the local model/configurator files cited above and `src/catalog/hand-nuts.ts`.

Recommended implementation checks: affected `npm run parts:check -- <id>` runs; naming, shared catalog, exact-ID search, state reconciliation and physical composition tests. Any geometry/state cleanup needs real generated macro/native checks as required by AGENTS.md. This audit does not certify manufactured threads, dimensions, load ratings, lifting suitability or source fidelity.
